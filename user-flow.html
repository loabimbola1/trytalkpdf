1. Flow Architecture & Core Loop

The TalkPDF MVP operationalizes the learning-resolution loop to isolate conceptual misconceptions, force active comprehension via Explain-Back, and verify gap closure through empirical past-question testing.

Linear Resolution Pipeline
1. ASSESS → 2. IDENTIFY LIKELY GAP → 3. TARGETED INTERVENTION → 4. EXPLAIN-BACK → 5. AI EVALUATION → 6. ONE RETRY IF NEEDED → 7. PARALLEL QUESTION → 8. RESOLVED / PERSISTENT → 9. PARENT UPDATE

2. Step-by-Step User Flow

Phase 1: Diagnostic Assessment
1
Entry & Syllabus Objective Selection
Student
User Action: Student opens TalkPDF mobile web/PWA on an entry-level smartphone. Selects target exam (WAEC or JAMB), subject (e.g., Physics), and a specific syllabus objective (e.g., Electromagnetism: Faraday's Law).
System Logic: Loads 5-question curriculum diagnostic module (FR-01). Initializes local storage cache for offline/asynchronous session recovery (FR-10).
State: SESSION_INITIALIZED → DIAGNOSTIC_ACTIVE
2
Diagnostic Quiz Completion
Student
User Action: Student answers 5 multiple-choice past-exam questions linked directly to the chosen syllabus objective.
System Logic: Records selected options against pre-tagged question metadata. Text-only lightweight payload guarantees zero data lag on 2G/3G networks (FR-08).
State: DIAGNOSTIC_SUBMITTED
Phase 2: Diagnosis & Micro-Intervention
3
Likely Learning-Gap Identification
System
System Action: When a student picks an incorrect option, system instantly isolates the pre-tagged misconception attached to that option (FR-02).
Presentation: Displays Question Result (Incorrect) and identifies the associated likely learning gap (framed as a probable misconception, not a definitive claim). Example: "Likely Gap Identified: Confusing magnetic flux with rate of change of magnetic flux."
State: LIKELY_GAP_IDENTIFIED
4
Targeted Micro-Intervention
Student
User Action: Student reads or listens to a bite-sized, 60–90 second plain-English conceptual micro-lesson focused strictly on the identified misconception (FR-03).
System Logic: Rendered as lightweight plain text and key diagram formulas with optional voice snippet. No multi-hour videos or unstructured PDF dumps (FR-08, FR-18, FR-19).
State: INTERVENTION_CONSUMED
Phase 3: Active Recall (Explain-Back Loop)
5
Explain-Back Active Recall Input
Student
User Action: Student is prompted: "Explain this concept in your own words so an SS1 student could understand." Student types their explanation into the text box or uses audio voice-note dictation (FR-04, FR-12).
System Logic: Real-time local storage caching ensures no drafted explanations are lost if data connection drops (FR-10).
State: EXPLAIN_BACK_SUBMITTED
6
Hybrid Human-Defined + AI Evaluation
System
System Action: AI evaluates student explanation against human-curated required-understanding points for that specific objective (FR-05).
Outputs: 1. Primary Mastery Gate: Evaluates to either UNDERSTOOD or NEEDS_CLARIFICATION.
2. Secondary Feedback Scores: Simplicity /10, Accuracy /10, Analogies /10, Overall /100, Badge (Gold/Silver/Bronze) — preserved as formative feedback signals.
Branching: If UNDERSTOOD → Advance to Step 8. If NEEDS_CLARIFICATION → Trigger Step 7 (Retry).
7
Targeted Hint & Single Retry (Conditional)
Student
Condition: Triggered only when evaluation returns NEEDS_CLARIFICATION.
User Action: Student receives 1 targeted conceptual hint pointing out missing required-understanding elements. Student submits exactly 1 refined retry (FR-04, FR-05).
System Logic: Evaluates retry. Regardless of second score, flow immediately advances to empirical testing (Step 8) to prevent endless chatbot loops.
State: RETRY_EVALUATED → READY_FOR_PARALLEL
Phase 4: Empirical Reassessment & Gap Closure
8
Parallel Reassessment Past Question
Student
User Action: Student is presented with 1 fresh, parallel past-exam question testing the identical syllabus objective (FR-06). Student solves and submits.
System Logic: Grades answer instantaneously against verified WAEC/JAMB marking scheme.
State: PARALLEL_ANSWER_SUBMITTED
9
Learning-Gap Status Resolution
System
Resolution Branches:
PROVISIONALLY_RESOLVED If parallel answer is correct → Gap marked provisionally closed, streak updated (FR-14), queued for longitudinal confirmation.

PERSISTENT_GAP If parallel answer is incorrect → Gap flagged as unresolved (FR-11), system displays human tutor escalation prompt (FR-13) with diagnosis pre-attached.
Mastery Integrity: No single question claims permanent mastery; future reassessment confirms or reopens the gap.
Phase 5: Parent Visibility & Accountability
10
Scorecard & Parent Deliverables Generation
System
System Action: Generates dual parent deliverables (FR-07, FR-09):
1. WhatsApp Summary: Short text update detailing gaps identified, provisionally resolved, requiring support, and readiness change ($X \to Y$).
2. Private Web Report: Secure, non-guessable, read-only, revocable link with detailed evidence and zero parent login barriers.
State: PARENT_REPORT_GENERATED
11
Parent Review & Tutoring Action
Parent
User Action: Parent receives WhatsApp summary on their phone. Sees tangible proof of study time and closed gaps. Taps private link for full evidence.
Outcome: If persistent gaps are flagged, parent directs evening lesson tutor strictly to those topics, eliminating wasted tuition spend. Both student and parent goals achieved!
State: CYCLE_COMPLETE

4. Edge Cases & Resilient Fallbacks

Intermittent Network Drop
Explain-Back drafting is continuously cached in browser local storage. Students reconnect and continue without lost progress (FR-10).
Unintelligible Audio Dictation
If noisy environment corrupts speech-to-text, system seamlessly falls back to text input without failing the active cycle (FR-08, FR-12).
Repeated Retry Failure
No infinite chatbot loops. After 1 hint and 1 retry, student directly takes the parallel question. If failed, cleanly flagged as PERSISTENT_GAP (FR-11).
Expired / Revoked Link
Private report URLs are non-guessable and revocable. Expired links present a secure prompt to request a fresh link via registered WhatsApp.
